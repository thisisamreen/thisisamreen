### 🧠 Physics-Aware ML

I like models that are not only statistically accurate, but also **physically meaningful**.

For HVAC systems, a prediction can have a good RMSE and still be wrong if it violates thermodynamics.

That means thinking about:

```text
data quality
+ seasonality
+ operating regimes
+ physical constraints
+ model metrics
+ production behaviour
```

instead of optimizing a metric in isolation.

## Principles

* **Physics before metrics.**
  A low RMSE means little if the prediction violates how the real system behaves.

* **Production over notebooks.**
  Training a model is only one part of ML engineering. Data pipelines, deployment, monitoring, failure handling, and retraining matter just as much.

* **Data is part of the model.**
  Missing seasonal coverage, sensor faults, distribution shifts, and weak features can matter more than another round of hyperparameter tuning.

* **Measure before optimizing.**
  Diagnose the bottleneck before adding complexity.

* **Simple systems earn complexity.**
  Start with the smallest architecture that explains the problem. Add complexity only when the data proves you need it.

* **Understand before abstracting.**
  I like knowing what happens underneath the API — whether that is an ML model, a distributed pipeline, or a physical system.
